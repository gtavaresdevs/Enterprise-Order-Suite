## How to use this file

- This is the single register of open questions that span more than one doc. ADRs and docs cite questions by id (`Q-NN`). Questions local to one doc stay in that doc's `## Open questions` block (ADR-0016).
- **Q-01, Q-02 and Q-03 are answered** (2026-09-29; MASTER-PLAN §8a). Gabriel's open questions in group 1 are Q-04..Q-10; each blocks only the item in its "Blocks" column (several are parts of S2 or S3). Every other question is asked when the step it blocks starts (§8b L116, §8c L118, §8d L120). Gabriel may answer any of them earlier.
- Gabriel answers by id, in any language (D-10): `Q-07: b` or `Q-44: a, but no PHONE source`. Short answers are enough.
- Owner:
  - `Gabriel`: only Gabriel can answer. Claude never records an answer he did not give.
  - `Claude decides, Gabriel may override`: technical. Claude records its choice in the doc that needs it, sets this row to `Decided by Claude (YYYY-MM-DD)`, and Gabriel can reverse it until that doc is Reviewed.
- Status values: `Open`, `Answered (YYYY-MM-DD): <answer>`, `Decided by Claude (YYYY-MM-DD)`, `Dropped (<reason>)`.
- Rules for agents:
  - Never renumber or reuse an id. Never delete a row; change its Status.
  - A new question takes the next free id and goes in the group of the step it blocks. First check that no existing row covers it; extend that row instead.
  - When a row is answered, update the ADR or doc that cites it in the same change. An ADR becomes Accepted only on Gabriel's word (ADR-0016).
  - Recommendations are Claude's proposals, never decisions.
- Groups follow the step each question blocks. There is no S2 or S5 group: questions that block S2 (docs skeleton) are under "S1 (now)" because they are answered in the S1 review, and questions that feed S5 (scope page, NFR page, audit triage) are under the contract they shape.
- Source prefixes:
  - PF = `/mnt/project-files/`.
  - BE = backend repo `enterprise-order-suite`, branch `feature/ai-agent` @ `af2634e`.
  - FE = frontend repo `order-ui`, branch `Claude-Assisted-Development` @ `14a3cfd`.
  - MP = PF `planning/MASTER-PLAN.md`.
  - BR = PF `2026-09-16-business-rules-master-en.md` (the same file is in FE `docs/superpowers/specs/`).
  - MF = PF `2026-09-14-backend-integration-manifest.openapi.yaml` (manifest 0.4.0, the FE copy).
  - ARCH = PF `architecture/RESTAURANT-OPS-ARCHITECTURE.md`; AMD = PF `architecture/ARCHITECTURE-AMENDMENTS-PROPOSED.md`.
  - "phase-0 design" = PF `2026-09-24-restaurant-ops-phase-0-foundation-design.md`; "phase-1 auth design" = PF `2026-09-25-restaurant-ops-phase-1-auth-design.md`.
